# CLI experience

## Practice flow

1. Print the item title, focus, and prompt. Do not print answer, hint, or feedback.
2. Start the monotonic timer and ask the learner to attempt recall.
3. After explicit submission, stop the timer and show elapsed time.
4. Ask whether the attempt was demonstrated, partial, or not demonstrated and capture confidence.
5. If partial or failed, offer one action at a time: retry unaided, request hint, reveal worked feedback, or stop.
6. Print an evidence summary separating result from help used.
7. Print the scheduler proposal and its algorithm/context.
8. End with one next action, never a streak prompt.

## Output modes

Human mode uses concise plain text. `--json` emits stable typed output with no ANSI codes. Errors go to stderr and use non-zero exit codes. Prompts remain usable by keyboard and screen readers.

## Operational states

- Loading: only for bounded module or database work; name what is loading.
- Empty: explain how to add the first item.
- Error: name the invalid input and preserve state.
- Success: show what was recorded and its event id.
- Disabled: explain which capability or configuration is absent.
- Stale: identify the changed item version and require a fresh challenge.
- Destructive: require explicit confirmation for reset or migration rollback.
- Recovery: offer `doctor`, backup path, and the smallest safe action.

## Tone

Direct, calm, and challenging. No shame, pressure, streak loss, moral judgment, or inflated capability claim. Banking time is a valid recommendation.
